# Output Template — 成果物フォーマット

成果物は 1 つの markdown ファイル(例: `feature-inventory.md`)にまとめる。構成は以下の 5 セクション。

確信度は全セクション共通で次の 3 値を使う:

- `確定` — コードから直接読み取れた事実
- `推測` — 命名・文脈からの仮説(根拠を備考に書く)
- `不明` — コードからは判断できない(要調査リストに転記する)

---

## 1. 調査サマリ

```markdown
# 機能一覧 — [システム名]

## 調査サマリ

- 調査日:
- 対象: [リポジトリ/フォルダパス、ファイル数、概算行数]
- 言語・技術スタック: [例: VB6 (画面系) + C# WinForms (帳票系)]
- 画面数: XX / 機能数: XX(確定 XX / 推測 XX / 不明 XX)
- ソースが入手できていない依存: [COM/DLL 名、ストアドプロシージャ等]
- 調査の限界: 静的解析のみ(動的解析・ヒアリング・git 履歴なし)
```

## 2. 機能一覧(本体)

「画面 × 操作」を 1 行とする。画面を持たない機能(バッチ・帳票・連携)も同じ表に含める。

```markdown
## 機能一覧

| ID | 種別 | 画面/起点 | 操作 | 機能名(仮説) | 処理概要(What) | エントリポイント | 関連テーブル | 確信度 | 備考 |
|---|---|---|---|---|---|---|---|---|---|
| F-001 | 画面 | 受注入力 (frmOrder) | 登録ボタン | 受注登録 | 受注ヘッダ・明細を登録し在庫を引当 | frmOrder.frm: cmdSave_Click | T_ORDER(C), T_STOCK(U) | 確定 | |
| F-002 | 画面 | 受注入力 (frmOrder) | F5キー | 単価再計算 | 顧客区分=3 のとき特価マスタを参照 | frmOrder.frm: Form_KeyDown | M_PRICE(R) | 推測 | なぜ区分3のみ特別扱いかは不明 |
| F-003 | バッチ | (Timer) | 自動 | 締め処理 | 毎日? T_ORDER を集計し T_SUMMARY へ | mdlBatch.bas: ExecClose | T_ORDER(R), T_SUMMARY(C) | 推測 | 起動条件が設定テーブル依存 |
| F-004 | 帳票 | 受注入力 | 印刷ボタン | 受注伝票印刷 | order.rpt を出力 | frmOrder.frm: cmdPrint_Click | T_ORDER(R) | 確定 | |
```

種別の値: `画面` / `バッチ` / `帳票` / `連携` / `CLI`

記載ルール:

- 機能名(仮説)は Phase 4 で収集した業務語彙(UI 文字列由来)を優先して使う
- 処理概要は **What のみ**を書く。Why が読み取れない場合は備考に「〜の理由は不明」と明記する
- エントリポイントは `ファイル名: 関数/ハンドラ名` 形式で必ず書く(後から検証可能にするため)

## 3. CRUD マトリクス

```markdown
## CRUDマトリクス

| 機能ID \ テーブル | T_ORDER | T_STOCK | M_PRICE | T_SUMMARY |
|---|---|---|---|---|
| F-001 | C | U | - | - |
| F-002 | - | - | R | - |
| F-003 | R | - | - | C |

### 異常の検出
- どの機能からも書かれないテーブル: [列挙] → 列挙漏れ or 他システムからの書き込みの疑い
- どのテーブルも触らない機能: [列挙] → デッドコード候補
```

## 4. 業務用語集

```markdown
## 業務用語集

| 用語 | 出典 | 意味(読み取れた範囲) | 確信度 |
|---|---|---|---|
| 引当 | frmOrder の Caption / T_STOCK.allocated_qty | 受注時に在庫を確保する処理と推定 | 推測 |
| 顧客区分 3 | frmOrder の分岐 + M_CUSTOMER.cust_type | 特価適用対象。業務上の意味は不明 | 不明 |
```

コード値(マジックナンバー)は「どう分岐に使われているか(確定)」と「業務的な意味(多くは不明)」を分けて書く。

## 5. 要調査リスト

後工程(ヒアリング・ログ調査)への引き継ぎ事項。

```markdown
## 要調査リスト

| # | 事項 | なぜコードから判断できないか | 推奨される調査方法 |
|---|---|---|---|
| 1 | F-003 締め処理の実行タイミング | 設定テーブル M_CONFIG の値に依存 | 本番 DB の M_CONFIG を確認 |
| 2 | 顧客区分 3 の業務的意味 | コード値の定義がコードに存在しない | 利用部門ヒアリング |
| 3 | usp_CalcMonthlyClose の内容 | ストアド定義が未入手 | DB からの定義エクスポートを依頼 |
| 4 | F-010〜F-015 の利用実態 | 静的解析では使用有無を判別不能 | アクセスログ / テーブル更新日時の調査 |
```
